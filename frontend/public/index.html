Mobile JKN — Alur Layanan Peserta

Mobile JKN adalah aplikasi peserta BPJS Kesehatan. Di sandbox ini ia diperankan sebagai aktor: setiap aksi pengguna diterjemahkan menjadi panggilan GraphQL openIMIS, sehingga terlihat jelas konsep mana yang punya padanan di openIMIS dan mana yang tidak.

JKN
Disclaimer: tidak ada koneksi ke API BPJS (Mobile JKN / VClaim / P-Care). Ini murni simulasi edukatif di atas instance openIMIS milikmu.
Peta Konsep: Mobile JKN → openIMIS 
PESERTA                 MOBILE JKN              OPENIMIS
----------------------  ----------------------  -----------------------------------
Login (No. Kartu/NIK)   -> Peserta/{noKartu}    -> insurees(chfId)
Status kepesertaan      -> Status Peserta       -> policyEligibilityByInsuree
Kelas & hak manfaat     -> Kelas I/II/III       -> Product.code + Policy.ceiling
Tagihan iuran           -> VA / Kode Billing    -> Premium (receipt, amount, payDate)
Ganti FKTP              -> Pindah Faskes        -> updateInsuree(healthFacilityId)
Antrean online          -> Antrean              -> (tidak ada di openIMIS)
Riwayat pelayanan       -> Riwayat Pelayanan    -> claims(insuree_ChfId)
Pengaduan               -> Pengaduan            -> createTicket
Punya padanan di openIMIS
  • Identitas & data peserta
  • Status kepesertaan / eligibilitas
  • Hak manfaat & plafon
  • Riwayat pembayaran iuran
  • Penetapan FKTP
  • Riwayat pelayanan (klaim)
  • Pengaduan
Tidak ada di openIMIS
  • Antrean online
  • Virtual Account / kode billing
  • SEP & nomor rujukan VClaim
  • Kelas rawat sebagai field khusus
  • Integrasi SatuSehat

1. Alur Keuangan & Polis

Keluarga membayar iuran (Premium) → polis terbit → polis menentukan plafon yang dicover saat berobat.

2. Alur Pelayanan & Klaim

Pasien berobat → dokter mencatat ICD-10 & tindakan → RS menagih klaim → openIMIS memvalidasi & menghitung penggantian.

3. Status Klaim

2 Entered → 4 Checked → 8 Processed → 16 Valuated. Status 1 Rejected bisa muncul di tahap verifikasi.

4. Dua API

GraphQL (/api/graphql) untuk aplikasi internal & mutation; FHIR R4 (/api/api_fhir_r4/) untuk interoperabilitas.
